# Q10 Sufficiency Test

A surviving project would have to satisfy all of these:

1. Predict downstream task failure, not merely detect distribution shift.
2. Beat simple uncertainty and output-shift baselines.
3. Beat or materially complement SUDO/label-free performance estimators.[1]
4. Warn before target labels mature, with measured lead time.
5. Change one concrete action: acquire a small label sample before retraining.
6. Demonstrate transport across at least two genuinely different temporal/site shifts without inspecting warning-period labels.

None is established in Step 00. Therefore the sufficiency gate is `FAIL` for project creation, even though a narrow theory-only question remains conceivable.
